# 0009. 站点结构：湖边是门，屋里是目录

- 状态：已接受
- 日期：2026-09-17

## 背景

引入两个场景页（ADR-0008）之后，站点有了两组「入口」：

- 原来的首页：四层滚动视差的黄昏封面（ADR-0007）+ 最近写的 / 最近拍的 / 一段自述。
- 新的湖边场景：一幅画，三行字，一个小木屋。

两者都在争夺「第一眼」。而且它们要做的事不一样：
封面是**内容索引**（告诉你这里有什么），湖边是**气氛**（让你想进去看看）。

同时 `/about` 和 `/projects` 的关系在历史上翻过一次面：ADR-0001 曾把
`/projects` 列表折进 `/about`，`/projects` 只留重定向。

## 决定

**湖边是站点的门，屋里是站点的目录。原来的首页封面退役。**

| 路由 | 是什么 | 导航 |
|---|---|---|
| `/` | **湖边**。一幅画，三行字，点小木屋进屋 | 无 |
| `/room` | **屋里**。整站的目录，点桌上的东西去各个页面 | 无 |
| `/projects` | 做过的东西 + 学历 / 论文 / 比赛 / 助教 | 有 |
| `/notes`、`/notes/:slug` | 笔记 | 有 |
| `/gallery` | 影像 | 有 |

- **屋里就是「关于我」。** 不需要第四个页面去讲这件事 ——
  你正站在我的房间里。详细的学历 / 论文 / 比赛挂在 `/projects` 尾部，
  它们是「做过的东西」的自然延伸。
- 屋里有**三扇门**，每一个的悬停标签写的是**真实去向**，
  不是物件的名字：电脑 · 做过的东西（→ `/projects`）、
  相机 · 拍下的（→ `/gallery`）、书（→ `/notes`）。
  标签承诺什么，点下去就得给什么。
- **`/about` 删除。** 计算机热点改指向 `/projects`。
- **`/projects` 恢复为真实列表页**，撤销 ADR-0001 里「折进 `/about`」的那一步。
  ADR-0001 的**定位判断（个人主页，不是简历站）不变**，只有 `/projects` 的归属变了。
- **湖边不带导航和页脚**（`route.meta.scene`）。
  给景加导航条会把景压成装饰，也会多出一套并行的导航 ——
  湖边靠点小木屋走路。
- 主导航只放**能从屋里走到、且真的能读**的页面：项目 / 笔记 / 影像。
  「屋里」放在页脚 —— 它是个场景，不是一篇能读的文章，
  但得留个地方能进去，否则从搜索引擎直接落到 `/notes` 的人
  永远看不到这个站最想让人看的那一页。
- 场景页保留一个**隐形的 `<h1>`**（站名 + 一句话定位），
  给搜索引擎和读屏用。景里那三行字是气氛，不是标题。

## 后续调整（2026-09-17）

屋里页改了三处，其中第一条推翻了这个 ADR 里的一条决定：

- **屋里开始有导航**，透明浮在景上（`SiteNav` 的 `transparent` 属性 →
  `.nav--over-scene`：无底色、无边框，只有一层很淡的纸色渐变，
  否则导航文字压在米色水彩天空上读不清）。
  **理由改了**：屋里同时是「关于我」，从搜索引擎直接落到 `/room` 的人
  需要一个出口，而「回到湖边」按钮拿掉了。
  湖边仍然无导航无页脚，「场景没有导航」这条只对湖边成立。
- **「回到湖边」按钮删掉**（`RoomView` 的 `.back`）。
- **屋内顶部那行「桌上有三样东西，点点看」删掉**，
  换成笔记本上方的**简历摘要纸片**（`ResumeSheet.vue`）：
  教育背景 / 技术能力 / 竞赛获奖。
  技术能力只列四个组标题 —— 带概述会让纸片高到盖住笔记本（见 ADR-0008）。

屋里不给页脚：舞台是 100vh 且 `fixed`，页脚会被顶到屏幕外。
屋里也不叠纸感噪点（`App.vue` 的 `hasChrome`）。

## 后续调整（2026-09-17）

导航栏改版：

- **去掉站名字标**、**去掉明暗切换按钮**（见 ADR-0004 的修订）、
  **去掉 GitHub 外链**（桌面版与手机菜单两处；**页脚的 GitHub 保留**）。
- **导航改成透明**，并且**不再只是屋里页** —— 除湖边外的每一页都用同一套。
- **文字改成白色、加粗、带阴影**。阴影是为了让白字能落在深浅不一的插画上。
- **导航横向加宽**：单独用 90rem（`main.css` 的 `.nav-wide`），
  不动全站共用的 `.shell`（68rem，它决定长文阅读宽度）。

### ⚠️ 已知问题：白字在内容页上不清楚

实测 1440×900，导航文字所在区域的白字对比度：

| 页面 | 背景平均亮度 | 白字对比度 |
|---|---|---|
| 屋内 | 0.618 | **1.57:1** |
| /projects | 0.699 | **1.40:1** |

WCAG 正文要求 4.5:1，而这两页都远低于它，探针里还有完全隐形的像素。
内容页的 `--paper` 是 `#f6f3ec`（近白），白字压在上面基本看不见。

**这是已知且已接受的状态**：用户确认了内容页的背景后续会改，
改完白字才能站得住。在那之前，内容页的导航是低对比度的。

而且**首页并没有导航** —— 所以严格说，「内容页导航跟首页相同」
实现出来就是「所有有导航的页都透明 + 白字」。

## 后果

**被推翻的**：

- **ADR-0007 作废。** 四层滚动视差封面连同 `ParallaxCover.vue`、
  `main.css` 里的 `.plx*` 区块一起删除。
- 首页的**最近写的 / 最近拍的 / 一段自述**一并删除（原 `HomeView.vue`）。
  内容索引的职责交给了屋里的三扇门。
- **`gsap` 与 `gsap/ScrollTrigger` 从依赖里移除。** 它们只服务过那个封面，
  首页因此少下载约 40–70 KB（gzip）。
- `frontend/README.md` 的目录结构需要跟着改。

**保留的**：`resume.ts` 的数据**一个字都没删**。
它能到 `/projects` 尾部，是这次结构里唯一能安放它的地方 ——
屋里只有三扇门，其中两扇通向影像和笔记。

**净效果**：站点代码明显变小（两个场景组件 + 五个内容页），
但素材从 0 涨到约 850 KB（WebP 之后）。这个交换是整次集成的实质。
