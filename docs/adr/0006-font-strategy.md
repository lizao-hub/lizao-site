# 0006. 字体策略：标题自托管手写体，正文系统栈

- 状态：已接受
- 日期：2026-09-16

## 背景

新风格对排版的要求：

- 标题：手写体、圆体，或有书法韵味的现代宋体。**避免粗黑体和商务衬线体。**
- 正文：细圆体或人文黑体，字重偏细，行高 1.6-1.8。

原来的字体栈是：中文走系统无衬线（`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC`），标题用 `Press Start 2P`（像素字体，随像素语言一起退役，见 ADR-0002），代码用自托管的 `JetBrains Mono`。

难点：中文字体动辄 5-15 MB，正文用 webfont 不现实。

## 决定

**标题用自托管的开源中文手写体，正文继续走系统栈。**

- 标题字体：OFL-1.1 协议的开源中文手写 / 书法字体，自托管、按实际用字子集化。OFL-1.1 允许免费商用与网页嵌入；选型优先 Google Fonts 上已按 `unicode-range` 分片的中文手写体（Long Cang、Ma Shan Zheng、LXGW WenKai、Klee One、ZCOOL 系列等），可直接引入而无需自建子集管道。
- 正文字体：维持现有系统栈（`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC`）。中文正文用 webfont 的字节成本换不回相应的观感收益。
- 代码字体：保留 `JetBrains Mono` 自托管。
- 加载：`font-display: swap`，绝不阻塞首屏。

## 理由

标题是「手写感 / 日记感」唯一必须落地的地方；正文的字重和行高由系统字体的常规字重加上 1.6-1.8 行高就能达到「轻松」的要求。

只做标题子集，体积可以控制在很小；一旦正文也上 webfont，就要背上完整字集或一条持续维护的子集管道。

## 后果

- 需要在 `index.html` / 全局样式中引入标题字体，并在 Tailwind 的 `fontFamily` 里新增一个 `display` 条目（替换退役的 `pixel` 条目）。
- 标题的字体回退链要显式写清楚：自托管手写体 → 系统中文黑体，保证字体未加载时版面不崩。
- 若将来正文也想上 webfont，需要新开一条 ADR，并给出实际的体积与加载数据。
