# 0007. 首页封面采用四层滚动视差

- 状态：已接受
- 日期：2026-09-16

## 背景

ADR-0005 的原始包线明确写着「不做：滚动联动的视差」，理由是滚动路径上的逐帧计算是移动端掉帧和耗电的首要来源。

首页封面需要更强的沉浸感：一张风景拆成天空、山、树、前景四层，以不同速度上移，产生纵深。

## 决定

**首页封面使用四层滚动视差（GSAP ScrollTrigger）。同时放开 ADR-0005 对视差的禁令，范围是站内任意页面，但当前只有首页封面对用。**

被打开的是「能不能用」，不是「可以随便用」。下面这些仍然有效：

- `prefers-reduced-motion: reduce` 时必须完全不做视差，直接显示最终状态。
- 位移只允许走 `transform`，不碰会触发布局的属性。
- 视差的滚动通道长度要克制。首页封面是 150vh，不是demo 里的 180vh：访客应该很快看到正文，封面不该把人拦在门口。

## 两条例必守的技术约束

这两条是算出来的，不是试出来的。改 `data-speed` 之前先看。

**一、overhang 必须 >= 最大 speed。**

层的位移按「视口高的百分比」算。设 overhang = `ov`（CSS 里 `inset: -ov 0`），
层底初始在 `1 + ov`，上移 `s` 后到 `1 + ov - s`。要盖住视口底就需要：

```
1 + ov - s >= 1   →   ov >= s
```

当前最大 speed 是 0.70（前景层），所以 overhang 取 0.80。

**二、位移不能用 `yPercent`。**

`yPercent` 按层自身高度算，而层为了留余量上下各多 80%，高度是视口高的 2.6 倍。
用 `yPercent` 会把位移放大 2.6 倍，底部直接盖不住。

两个错误还会互相放大：overhang 越大 → 层越高 → `yPercent` 位移越大 → 越盖不住，
永远不会收敛。所以位移写成 `y: () => -speed * window.innerHeight`。

## 后果

- **包体积**：gsap 与 ScrollTrigger 加起来约 45 KB gzip。它们**只在首页动态引入**，
  不进主包（实测主包维持在 57.8 KB gzip，另切出 gsap 27.4 KB + ScrollTrigger 17.5 KB）。
  从 `/notes` 等其他页进来的访客不为封面付任何代价。
- **动画是渐进增强**：首屏文案先渲染，`is-pending` 只负责短暂隐藏。
  gsap 下载失败或用户开了「减少动态效果」时，这个标记会被撤掉，文案照常可见。
- **封面用的是手绘占位图，不是真图。** 现阶段用 CSS 渐变与内联 SVG 画出天空 / 山 / 树 / 前景，
  不依赖任何图片就能跑。换成真图的做法写在 `main.css` 的 `.plx__layer--*` 注释里：
  天空用不透明 JPG，山 / 树 / 前景用透明 PNG，四张同比例同视点。
- **旧的手绘首屏被替换。** 原来首屏右侧那张真实肖像移到封面下方自述区，
  两个 `drift` / `sway` 环境意象与其 keyframes 一并删除。
- **封面不受明暗主题影响。** `.plx__*` 里的颜色全部写死（黄昏景本身就是深的），
  一个主题变量都没用。这是有意的例外：一张黄昏插图不该因为切主题而变亮。
  换真图后同理，封面文字仍用固定浅色。
