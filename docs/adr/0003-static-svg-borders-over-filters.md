# 0003. 静态手绘 SVG 优先于运行时滤镜

- 状态：已接受
- 日期：2026-09-16

## 背景

要得到「非矢量完美」的手绘边框，有两条技术路线：

1. **运行时 SVG 滤镜**：用 `feTurbulence` + `feDisplacementMap` 实时扰动路径。
2. **静态手绘路径**：预先手绘一组 SVG 边框 / 分隔线 / 相框组件，复用。

滤镜方案在效果上更有吸引力：扰动无限可变，永远不会「看出重复」，也能让任何矩形瞬间变得手绘。

## 决定

**默认使用静态手绘 SVG 路径。** 小组件允许用廉价的 CSS 手法（非对称 `border-radius`、轻微 `rotate()`）。

运行时的 `feTurbulence` 滤镜只在**单个装饰性元素**上保留（如果确实需要那个会呼吸的抖动），不作为通用手法。

## 理由

- `feTurbulence` 在多元素上重复使用有真实的 repaint 开销；本站要保证在中端手机上不卡。
- 滤镜在不同浏览器（尤其 Safari）上的渲染结果不一致，手绘效果的「手感」会随浏览器漂移。
- 静态路径可以缓存、体积可控、在所有环境下**长得一样**。手绘质感的目的是「像人画的」，不是「每次都不同」。
- 复用一组作者手绘的路径，能保证边框、图标、分隔线共享同一条线质——这正是滤镜方案做不到的（它扰动的是几何，不是笔触）。

## 后果

需要提前设计并手绘一组路径素材：外框、内框、分隔线、相框、按钮底。这比「给所有元素挂一个 class」麻烦，是一次性成本。

同理，**纸张/噪点纹理**走内联 SVG `feTurbulence` 生成 data-URI 作 CSS 背景（一次生成，无运行时计算），而不是每页挂一个滤镜或者塞一张 PNG——见 ADR-0004 关于两种模式各需一套纹理的说明。

## 一条硬性限制：滤镜不能包住位图

`filter: url(#rough-edge)` 会作用于元素的**全部内容**，不只是边框。
所以 `.sketchy` 不能加在包着 `<img>` 的相框上：`feDisplacementMap` 会把照片
像素一起扭掉，人手一张变形的脸。

能用 `.sketchy` 的：内联 SVG、纯色块、装饰性图形。
不能用：任何含位图的容器。

要手绘边框又包着图，只能手绘路径本身，或者把边框做成覆盖在图片上的独立元素。
