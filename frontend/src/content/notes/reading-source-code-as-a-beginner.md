劝新手读源码的人通常忽略了一件事：新手不知道该读哪一行。

一个框架有几万行。从入口文件开始读，读到第三层就会迷路，因为这时候我既不知道这个函数为什么被调用，也不知道它的返回值会被谁用。信息是单向的，只能硬记。

我的做法反过来：从一次真实的报错出发，往上追。

## 第一步：制造一次报错

不是随便制造，是制造一次我已经知道答案的错。

比如我故意在模板里写一个不存在的字段 `{{ user.nmae }}`，看 Vue 会告诉我什么。报错里会带上组件名和行号，这就是入口。

## 第二步：在堆栈里找自己的文件

堆栈里会有七八行，其中只有一行是我写的。先找到那一行，记住它在哪个函数里被调用。

## 第三步：只往上看一层

这是最关键的一步，也是我一开始做错的地方。我会忍不住一路往上看十层，然后全部忘掉。

正确的做法是只往上看一层，问三个问题：

- 这个函数收到什么？
- 它返回什么？
- 它什么时候被调用？

回答完这三个问题，再往上走一层。慢，但记得住。

## 一个例子

我在写一个列表，切换筛选条件之后页面不更新。控制台里只有一句：

```
Unhandled error during execution of watcher callback
```

我顺着往上找，发现问题不在列表上，而在我的 `watch` 里：我监听的是一整个对象，但它内部某个属性变了，引用没变，所以回调没触发。

如果我从框架入口开始读，可能永远读不到这一行。从报错往上走三层就到了。

## 什么时候该从头读

有一种情况例外：我打算长期用这个框架，而且已经追过十几次报错了。

这时候从头读才有意义，因为我已经知道每个模块大概在解决什么问题，读的时候是在填空，不是在海里捞针。

顺序应该是这样：先追报错，后读源码。反过来会很痛苦。
