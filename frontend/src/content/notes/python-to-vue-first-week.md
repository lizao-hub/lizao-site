第一天我把 `let count = 0` 写进了 `<script setup>`，然后在模板里改它，页面纹丝不动。

在 Python 里，`count += 1` 之后 `count` 就是新值。在 Vue 里这句话也确实执行了，只是模板不会因为一个普通变量变化而重新渲染。它盯着的是 `ref` 和 `reactive` 里面的东西。

```ts
// 页面不会更新
let count = 0
count += 1

// 页面会更新
const count = ref(0)
count.value += 1
```

真正折磨我的是 `.value`。第一周我大概漏写了二十次，编辑器不报错，运行时不报错，只是页面上那个数字永远是 0。后来我给自己定了个笨办法：看到 `ref(` 就先把 `.value` 写上。

## 报错不指向你写的那一行

Python 的堆栈从下往上读，最后一行基本就是案发现场。前端的报错经常指向框架内部的某一行，我写的那一行反而在上面。

我花了三天才接受这件事：报错的位置是「框架在哪里放弃了」，不是我哪里写错了。真正有用的信息通常是紧跟着的那句 `at <ComponentName>`，它告诉我该回哪个文件看。

## 没有 return，模板就是 return

写 Python 的时候，返回值是我控制的东西。在 Vue 里，模板自己去读 `setup` 里暴露出来的东西，我找不到一个地方写「返回这个」。

我一直在找一个 `return` 来放我的数据，找不到，很慌。后来想通了：`<script setup>` 里的顶层绑定就是返回值，模板是那个自动生成的 `return` 语句。

## 一周之后

七个坑里，五个是心智模型的问题，两个是记性问题。

如果让我给同样从 Python 转过来的人一句话：不要试图在前端里找 Python 的对应物。响应式不是一个更聪明的变量，它是另一套东西。
